# What is a Token?

A **token** is the smallest unit of text that an LLM processes.

A token is **not always a word**.

Sometimes a token can be:

- A word
- Part of a word
- A punctuation mark
- A number
- A symbol

Example:

Sentence

```
I love Java.
```

Possible tokens

```
I
love
Java
.
```

---

# Characters vs Words vs Tokens

Example

```
Spring Boot is awesome.
```

| Type | Example |
|------|----------|
| Characters | 24 |
| Words | 4 |
| Tokens | ~5-7 |

Notice that:

Characters ≠ Words ≠ Tokens

---

# Why Do LLMs Use Tokens?

LLMs do not understand English.

They understand numbers.

The tokenizer converts text into tokens.

```
User Prompt

↓

Tokenizer

↓

Token IDs

↓

LLM

↓

Generated Tokens

↓

Response
```

---

# Tokenization

Example

Sentence

```
unbelievable
```

Possible tokens

```
un

believ

able
```

Another example

```
SpringBoot
```

may become

```
Spring

Boot
```

Different models may tokenize the same sentence differently.

---

# Input Tokens

Input tokens are everything you send to the model.

Example

```
Explain Spring Boot.
```

The model first converts this into tokens.

---

# Output Tokens

Output tokens are the tokens generated by the model.

Example

```
Spring Boot is a Java framework...
```

This response also consumes tokens.

---

# Total Tokens

```
Total Tokens

=

Input Tokens

+

Output Tokens
```

Example

Input

```
200 Tokens
```

Output

```
300 Tokens
```

Total

```
500 Tokens
```

---

# Why Tokens Matter

Tokens affect

- Cost
- Speed
- Context Window
- Performance

More tokens

↓

More processing

↓

Higher cost

---

# Token Limits

Every model has a maximum context window.

Example

| Model | Approx Context |
|--------|----------------|
| Llama 3 | 8K |
| GPT-4.1 | Much larger (varies by version) |
| Claude | Large context support |

If you exceed the limit,

older tokens may be discarded or the request may fail depending on the model.

---

# Token Pricing

Cloud AI providers usually charge based on tokens.

```
More Tokens

↓

Higher Cost
```

Example

Small Prompt

↓

Cheap

Large Prompt

↓

Expensive

---

# Token Optimization

Good practices

✅ Send only necessary information

✅ Remove duplicate text

✅ Chunk large documents

✅ Summarize previous conversation

✅ Use RAG instead of sending entire PDFs

---

# Tokens in Spring AI

When using Spring AI

```
User

↓

Spring Boot

↓

Spring AI

↓

LLM

↓

Response
```

Spring AI sends your prompt to the model.

The model counts

- Input Tokens

and

- Output Tokens

Some providers also return token usage in the response metadata.

---

# Real-world Example

Suppose a customer uploads

```
300-page PDF
```

Never send the entire PDF.

Instead

```
PDF

↓

Chunking

↓

Embeddings

↓

Vector Database

↓

Relevant Chunks

↓

LLM
```

This reduces token usage significantly.

---

# Best Practices

- Keep prompts concise.
- Avoid repeating instructions.
- Use RAG for large documents.
- Cache repeated prompts when appropriate.
- Monitor token usage in production.

---

# Common Mistakes

❌ Sending an entire database dump

❌ Sending a complete PDF

❌ Repeating the same prompt

❌ Ignoring token costs
